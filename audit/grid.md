# Grid parity audit

## Verdict

**No — grid is not at complete feature parity.** The structural shell is present and several low-level primitives are faithful ports (sparse `CellOccupancyMatrix`, line/coordinate conversions, most `style/grid` constructors/predicates, the `find_size_of_fr` restart loop), but the algorithms that actually decide track sizes are simplified approximations rather than ports. The Zig entry point `compute_grid_layout` (`src/compute/grid/mod.zig:174`) never calls the faithful `initialize_grid_tracks` (`explicit_grid.zig:119`), `align_tracks` (`alignment.zig:52`) or `compute_grid_track_offsets` (`track_sizing.zig:592`); instead it builds a compact `Track` list whose fr/gap math double-counts leading/trailing gutters, and item intrinsic contributions are never measured (one cached measurement is reused for min-content, max-content, and minimum contribution). The full CSS Grid §11.5 sub-phase pipeline, baseline shimming, alignment-gutter adjustments, percentage re-resolution/rerun, RTL, absolute-item name resolution, container aspect-ratio/contain/scrollbar handling, and `detailed_layout_info` population are missing or unwired. No Zig fixture harness exists (2,248 grid XML + 565 grid HTML fixtures in the reference are unrunnable), so none of this is currently caught by tests.

## Covered and behaviorally aligned

- **Sparse cell occupancy.** `types/cell_occupancy.zig` mirrors the Rust interval model almost line-for-line: `paint` overwrite/merge, `collision_extent`, `last_of_state`, `mark_area_as`, `expand_to_fit_range`, `line_area_collision_jump`, `occupied_track_jump` (Zig `:55-279`; Rust `types/cell_occupancy.rs:67-375`). The Zig test at `cell_occupancy.zig:282` is a thin subset of the Rust 10-test module.
- **Coordinates and counts.** `MAX_GRID_TRACKS=10_000`, `MIN_OZ_LINE=-10_000`, `MAX_OZ_LINE=10_000` and the line→index/implied-track conversions match Rust `types/coordinates.rs:13-19,49-153` (Zig `coordinates.zig:57-168`; `grid_track_counts.zig:15-53`).
- **Style value vocabulary.** `GridPlacement` conversion helpers, `line_resolve_definite_grid_lines`, `line_resolve_absolutely_positioned_grid_tracks`, `into_origin_zero_placement_ignoring_named` are behaviorally equivalent for non-named lines (Zig `style/grid.zig:225-357`; Rust `style/grid.rs:537-710`). `compact_length.zig` tag predicates match `compact_length.rs`.
- **Explicit auto-repeat arithmetic.** The CSS fit math (first-repetition overflow → 1; floor/ceil +1; insertion-point clamp) matches Rust for templates whose tracks satisfy `has_fixed_component` (Zig `explicit_grid.zig:27-116`; Rust `explicit_grid.rs:27-217`); Zig tests at `explicit_grid.zig:156-181`.
- **`find_size_of_fr` restart rule.** Zig `track_sizing.zig:494-515` implements the oversized-base restart with the same iteration bound as Rust `track_sizing.rs:1380-1440`.
- **Basic plumbing exercised by Zig tests.** Fixed-track gap offsetting, padding-aware fr sizing (no gap), child clamping to min-width, display:none exclusion, simple absolute placement, negative implicit line placement: `mod.zig:576-778`. These tests pass only by construction of narrow cases; see divergences below.

## Missing or unimplemented

Format: what Rust does (Rust file:line) → what Zig does (Zig file:line) → impact → severity.

1. **Item intrinsic measurement.** Rust measures the child per contribution type and caches it: min-content (`types/grid_item.rs:482-527`), max-content (`:529-602`), minimum contribution incl. automatic-minimum rules and spanned fixed limits (`:604-706`), using `known_dimensions`/keyword-adjusted available space (`:280-378,559-586`). Zig's `min_content_contribution`/`max_content_contribution`/`minimum_contribution` (`types/grid_item.zig:208-249`) only read caches; they never call the child measurement API. The single measurement that fills those caches is `size_tracks` (`mod.zig:434-453`), which runs one `compute_size` call with `available_space = max_content` and writes the same value into all three caches. `measured_intrinsic_size`/`set_measured_intrinsic_size` (`grid_item.zig:261-266`) have no callers. **Impact:** intrinsic track sizing (text/content-driven tracks, `min-content`/`max-content`/`auto`, automatic minimum size) is wrong in general; the 137 `grid_flex_track_intrinsic*` + 31 `grid_intrinsic_track_sizes*` fixtures target exactly this. **BLOCKER.**

2. **CSS Grid 11.5 intrinsic sizing sub-phases.** Rust runs six ordered steps with planned increases/infinitely-growable state, scroll-container quirk, limited contributions, flex-factor-proportional distribution and “distribute beyond limits” (`track_sizing.rs:555-1020`, helpers `:1031-1241`). Zig has one merged loop `resolve_intrinsic_grid_track_sizes` (`track_sizing.zig:434-490`) that equal-splits a single deficit across spanned intrinsic tracks and raises growth limits by `base + share`. `spans_track_matching`, `item_incurred_increase`-based phased flushes are unused. **Impact:** every content-sized spanning item is sized by a different algorithm than Taffy. **BLOCKER.**

3. **Baseline alignment (track sizing shim + container baseline).** Rust shims baseline-aligned items per row (`track_sizing.rs:461-551`), detects `has_baseline_aligned_item` (`mod.rs:306`), and returns the container’s first baseline (`mod.rs:832-875`). Zig defines `participates_in_baseline_alignment` (`grid_item.zig:85-87`) but never calls `resolve_item_baselines`; `align_item_within_area` treats baseline as start (`alignment.zig:90`); `compute_grid_layout` never computes a baseline and returns `LayoutOutput.from_outer_size` (`mod.zig:255`), so `baselines` in `LayoutOutput` (`tree/layout.zig:82-106`) stays empty. **Impact:** `align-items/self: baseline` track heights and parent baseline queries differ; 19 `*baseline*` fixtures. **MAJOR.**

4. **Alignment gutter adjustment.** Rust computes `content_alignment_adjustment` for inner gutters used when estimating the opposite axis (`track_sizing.rs:180-240,316-328`). Zig stores the field (`grid_track.zig:11`) but `grid_track_sizing_algorithm` never sets it; `grid_area_size_for_tracks` adds it (`grid_item.zig:188`) but has no callers. **Impact:** opposite-axis size estimates for content-sized items are off whenever `align/justify-content` is spacing-based. **MAJOR.**

5. **Percentage track re-resolution and sizing reruns.** Rust re-resolves percentage tracks against the computed content box when the container size was initially indefinite and conditionally re-runs column/row sizing and contribution caches (`mod.rs:379-403`, `405-561`). Zig runs `size_tracks` once (`mod.zig:240-241`); `track_is_intrinsic_for_minimum` has a percentage-as-min-content branch (`track_sizing.zig:365-372`) but there is no re-resolution or rerun. **Impact:** `grid-template-columns: 50%` in an auto-sized grid can stay at its first-pass size; 41 `*percent*` fixtures. **MAJOR.**

6. **Flexible-track expansion bounds and indefinite/max-content behaviour.** Rust expands fr using the min/max-size clamp, max-content contributions under indefinite constraints, and factor-proportional `0fr` handling (`track_sizing.rs:1275-1374`). Zig only expands in the definite branch (`track_sizing.zig:557-568`); under `.max_content` fr tracks stay at base size (0) and `axis_min_size`/`axis_max_size` inputs are unused. **Impact:** content-sized grids with `fr` collapse instead of content-sizing. **MAJOR.**

7. **`detailed_layout_info` never populated.** Rust builds `DetailedGridInfo` and calls `tree.set_detailed_grid_info` (`mod.rs:794-814`; types `mod.rs:878-1183`). Zig defines `DetailedGridInfo`/`DetailedGridTracksInfo` (`mod.zig:29-160`) but `compute_grid_layout` never constructs or stores them; `TaffyTree.detailed_layout_info` (`taffy_tree.zig:260-261`) always returns `.none`, and `traits.set_detailed_grid_info` (`traits.zig:110-111`) is a no-op unless a callback is installed. The 7 tests in `tests/hand_written/detailed_grid_info.rs` (line names, repeat expansion, implicit lines, `item_grid_area`, absolute named span, RTL order) cannot be run. **Impact:** the feature’s public API returns nothing. **MAJOR.**

8. **Named-line resolver is unused; repeat()/area line-name expansion missing.** Rust builds a `NamedLineResolver` that expands line names through `.count` and auto repeats, handles `NamedSpan` relative to the opposite edge, and falls back per spec (`types/named.rs:102-350`; consumed at `placement.rs:48-60`). Zig’s `named.zig` exists (`:71-221`) but no layout code calls it (`from_style` at `:92` is dead); placement uses its own `resolve_named_placement` (`placement.zig:82-113`) that only reads the flat `style.grid_template_column_names`/`grid_template_row_names`, does not expand line names declared inside `repeat()`, and treats `named_span` as an ordinary span. **Impact:** named lines from repeats and named spans resolve differently. **MAJOR.**

9. **Auto-placement structure (step 2, collision jumps, sparse cursor).** Rust places definite-secondary-axis items in a dedicated step using `last_of_type` for sparse (`placement.rs:89-117,200-233`), then step 4 uses `occupied_track_jump` for spans-all-primary and collision jumps (`:237-343`). Zig runs one merged auto pass in source order (`placement.zig:248-277`) with cell-by-cell probing; `last_of_type`/`occupied_track_jump` (`cell_occupancy.zig:245-279`) are unused; sparse cursor is “advance one cell” rather than Rust’s `(primary_span.end, secondary_span.start)`. **Impact:** sparse/dense placement can differ from Taffy for mixed definite/auto items; Rust placement tests `test_fixed_in_secondary_axis`, `test_definite_in_secondary_axis_with_fully_definite_negative`, `test_sparse_packing_algorithm`, `test_auto_placement_in_negative_tracks` have no Zig analogue. **MAJOR.**

10. **RTL.** Rust aligns columns with `axis_is_reversed` and assigns physical offsets right-to-left, including item and absolute-item mirroring (`alignment.rs:23-83`; `mod.rs:568-592,611-624,738-757`). Zig’s `align_track_sizes` (`alignment.zig:18-47`) has no direction parameter and `place_children` computes logical left-to-right offsets (`mod.zig:473-514`); only per-item alignment receives `container.direction`. **Impact:** 23 `rtl`/`direction` fixtures. **MAJOR.**

11. **Absolute items resolved through the name resolver and border-box fallback.** Rust resolves absolute placement via `name_resolver.resolve_*_names` + `line_as_start_edge`/`line_as_end_edge` and handles `auto` edges against the border box (`mod.rs:670-792`). Zig assigns absolute children a placement during in-flow placement (`placement.zig:226-233`) and positions them from the compact track list (`mod.zig:473-514`); named resolution goes through the reduced `resolve_named_placement`. **Impact:** absolutely positioned grid items with named/auto edges and RTL can differ. **MAJOR.**

12. **Container aspect-ratio, contain, scrollbar gutters, overflow/content-size outputs.** Rust resolves container aspect ratio into min/max/preferred sizes (`mod.rs:63-89`), reserves scrollbar gutters (`:91-109`), short-circuits `ComputeSize` (`:155-168`), and returns scrollable-overflow + baselines for `content_size` (`:816-875`). Zig `compute_grid_layout` references none of `aspect_ratio`, `contain`, `overflow`, `scrollbar_width`; it always runs the full path and returns `from_outer_size` only. **Impact:** grid containers with aspect-ratio/scroll overflow report wrong size/overflow and suppress-baseline behaviour; root/child layout caches see different outputs. **MAJOR.**

13. **Keyword item sizes and keyword-adjusted available space.** Rust resolves `stretch`/`min-content`/`max-content`/`fit-content` item sizes with dedicated measure calls (`alignment.rs:192-341`) and adjusts available space when the style size is a sizing keyword (`grid_item.rs:559-586`). Zig `place_children` only calls `Dimension.resolve` and otherwise reuses `child.unrounded_layout.size` (`mod.zig:487-488`); `GridItem.keyword_adjusted_available_space` (`grid_item.zig:251-259`) and `known_dimensions` (`:139-158`) are never called. **Impact:** `width: min-content` etc. on grid items is ignored. **MAJOR.**

14. **Gap accounting in track sizing (leading/trailing gutters).** Rust collapses the first/last gutter (`explicit_grid.rs:365-367`), so only inner gaps participate in `initialize_track_sizes`, `find_size_of_fr` and sum totals. Zig `size_tracks` prepends a `gutter(gap)` before every track and appends one after every track (`mod.zig:397-405`) and never collapses the outer two; `initialize_grid_track_sizes` gives every gutter a base size equal to `gap` (`track_sizing.zig:353-363`). **Impact (static finding, not runtime-verified):** `used` space in `find_grid_fr_size` (`track_sizing.zig:502-506`) includes two extra gaps, so `1fr` with any non-zero gap is undersized by `2*gap/factor`, and auto-sized container content is overestimated by two gaps per axis. **BLOCKER** if confirmed.

15. **`repeat()` line names / template validity edge cases.** Rust truncates template expansion at the explicit limit and ignores invalid templates when `counts.explicit == 0` (`explicit_grid.rs:275-352`). Zig `expand_template` (`mod.zig:258-267`) always emits at least one repetition (`@max(auto_repetition_count,1)`) even when `compute_explicit_grid_size_in_axis` returned 0 (invalid template), so invalid `repeat(auto-fill, 1fr)` creates a track while Rust creates none. **MINOR–MAJOR.**

## Present but behaviorally divergent

1. **`has_fixed_component`.** Rust: `min.is_length_or_percentage() || max.is_length_or_percentage()` (`style/grid.rs:1453-1455`). Zig: `min.value == .length and max.value == .length` (`style/grid.zig:646-648`). `repeat(auto-fill, minmax(100px, 1fr))` is valid in Taffy but rejected in Zig (and percentages rejected), discarding auto-repeat sizing. **BLOCKER** for auto-fill/fit with `minmax`.

2. **Bare `fr`/`fit-content()` min track.** Rust maps a bare fr/fit-content max to a min of `auto` (`style/grid.rs:1181-1187`). Zig `TrackSizingFunction.from_str` copies the raw max value into `min` (`style/grid.zig:692-693`), so a `1fr` track’s min is `.fr` instead of `.auto`; the automatic-minimum contribution path (`track_sizing.zig:365-372,454-465`) is skipped. **MAJOR.**

3. **Track sizing driver.** Zig `grid_track_sizing_algorithm` (`track_sizing.zig:553-588`) keeps only: initialize → merged intrinsic → maximize (finite limits only, `:520-542`) → fr expansion (definite only) → optional stretch (never enabled from grid: `mod.zig:461` passes `stretch_auto_tracks=false`). Rust orders: initialize → baseline shim → intrinsic six-step → maximize → expand flexible (with min/max) → stretch auto (`track_sizing.rs:288-379`). Iteration order and rounding therefore differ (Zig’s equal-share `distribute_intrinsic_deficit` vs Rust’s freeze-at-limit loop with `THRESHOLD=0.01`, `track_sizing.rs:1477-1537`).

4. **Stretch auto tracks.** Rust stretches only tracks whose max function `is_auto()` (`track_sizing.rs:1445-1472`). Zig stretches any compact track with `fr == 0 and max == null` in `align_track_sizes` (`alignment.zig:27-38`); append_track_marked sets `max = null` for percent, min-content, max-content, fit-content and auto maxima (`mod.zig:278-283`). **Impact:** default `justify-content/align-content: stretch` over-expands non-auto tracks. **MAJOR.**

5. **Container size clamp.** Rust clamps resolved size by min/max and floors at padding+border (`mod.rs:355-372`, `139-149`). Zig clamps with `clamp_resolved_size` but has no `.max(padding_border_size)` (`mod.zig:243-247`), no aspect-ratio resolution and no `constrained_available_space` min/max clamp (`mod.rs:123-128`). **MINOR–MAJOR.**

6. **Item alignment helper.** Rust `align_item_within_area` receives already-resolved self-start/self-end and handles both-insets absolute + RTL (`alignment.rs:424-506`). Zig’s version returns 0 for `self_start/self_end` (`alignment.zig:93`), doesn’t resolve them against direction, and its absolute branch only handles one-sided insets for LTR (`:95`). **MAJOR** with RTL/`self-start`.

7. **Child layout call in `place_children`.** Rust always passes `Size<Option<f32>>` (nulls preserved) and `grid_area_minus_item_margins_size` as available space (`alignment.rs:328-350`). Zig always passes definite `known_dimensions` (`mod.zig:498-507`), falling back to the stale `child.unrounded_layout.size` from the pre-pass (`:487-488`), so auto-sized children are pinned to a previous measurement. Margins, padding/border, scrollbar_size, `order`, `scrollable_overflow_rect` are not written on the child by the grid path. **MAJOR.**

8. **`MaxTrackSizingFunction` predicates.** Zig `is_max_content_alike` includes `min_content` (`style/grid.zig:553-555`) whereas Rust excludes it (`style/grid.rs:950`; `compact_length.rs:446-454`). Zig `definite_limit` omits fit-content arguments (`style/grid.zig:586-588`) whereas Rust includes them (`style/grid.rs:1027-1037`). Zig `MinTrackSizingFunction.is_min_or_max_content` includes `auto` (`style/grid.zig:416-418`) whereas Rust allows only min/max content (`style/grid.rs:1307`). **MINOR–MAJOR** depending on call site.

9. **Explicit grid auto-fit strategy.** Rust chooses `MinRepetitionsThatDoOverflow` when only a definite min size exists (`mod.rs:196-199`). Zig always passes `max_repetitions_that_do_not_overflow` (`mod.zig:192-193`). Percentage gap basis is also parent-width for both axes in Zig (`mod.zig:563-565`) rather than the relevant axis inner size (`explicit_grid.rs:156`). **MINOR.**

10. **Positive implicit track cycling.** Rust restarts `grid-auto-*` cycling at index 0 for trailing implicit tracks (`explicit_grid.rs:357-363`). Zig continues from `output.items.len` (`mod.zig:291-298`, `explicit_grid.zig:147-154`). **MINOR.**

11. **`line_resolve_indefinite_grid_tracks`.** Zig ignores an end span when start is auto (`style/grid.zig:359-362`); Rust handles `(Auto, Span(span))` (`style/grid.rs:701-710`). Currently unreferenced by layout. **MINOR** (latent).

12. **`align_track_sizes` details.** Free space is clamped to `>= 0` (`alignment.zig:25`) vs Rust’s signed free space; fallback count uses `tracks.len` rather than non-collapsed track count (`:26`); collapsed tracks are skipped for gaps via `preceding_track_extent`/`track_area_extent` (`mod.zig:516-554`) rather than track offsets, so empty auto-fit grid line positions are approximated. **MINOR.**

13. **Item batching/sorting.** Rust’s `ItemBatcher` groups items by (crosses-flex, span) with stable ordering (`track_sizing.rs:16-63,574`). Zig sorts with `std.sort.heap` (`track_sizing.zig:147-153`) and does not batch; ties may order differently. Distribution is equal-share, not per-phase. **MAJOR** (subsumed by item 2 of Missing).

14. **`calc()`.** `CompactLength.calc` exists and `compact_length.zig:82-84` counts it as percentage, but `Min/MaxTrackSizingFunction.definite_value` ignore `.calc` (`style/grid.zig:439-445,578-584`), and `TaffyTree.resolve_calc_value` returns 0 (`taffy_tree.zig:326-329`). Rust resolves calc through `tree.calc` (`style/grid.rs:1014-1015,1347-1348`). **MINOR–MAJOR** where `calc()` tracks are used.

## Feature flags / API surface affected

- **`detailed_layout_info`**: types + serializers exist but are never produced at runtime (see Missing 7). No Zig build option exists; the API is always compiled yet inert.
- **`content_size`**: no explicit feature flag; grid returns only an outer size (`mod.zig:255`). A generic post-pass `compute_node_scrollable_overflow` (`compute/mod.zig:38-58`) substitutes at the cache boundary, but grid items’ stale pre-pass `scrollable_overflow_rect` and missing absolute-item union mean scroll extents can differ from Rust’s `content_size` path (`mod.rs:859-875`).
- **`calc`**: value tag exists but is not resolved in grid track sizing or insets (see Divergent 14).
- **`parse`**: `style/grid.zig` exposes `from_str`/`grid_template_component_from_str`, but no stylesheet parser in `src/` populates grid template line-name arrays from `repeat()` line names; `named.zig:from_style` is the only consumer and is unused.
- **Grid feature gating**: Taffy’s `grid`/`block_layout`/`flexbox` cfg features have no Zig analogue; grid is always compiled and dispatched for `display: grid` (`compute/mod.zig:85-90`).
