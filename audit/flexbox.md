# Flexbox parity audit

## Verdict

**No — flexbox is not at feature parity, and several core flexbox behaviors are missing or wrong, not merely approximated.** The Zig `src/compute/flexbox.zig` (961 lines vs Rust 3615) reproduces the phase *names* of Taffy 0.14, but nine of the phase functions it declares are dead stubs or no-ops (`calculate_cross_size`, `handle_align_content_stretch`, `determine_used_cross_size`, `distribute_remaining_free_space`, `resolve_cross_axis_auto_margins`, `align_flex_items_along_cross_axis`, `determine_container_cross_size`, `align_flex_lines_per_align_content`, `determine_container_main_size`; `determine_available_space` is a no-op and `item_known_dimension_definiteness` is never called), and the live code paths diverge from Taffy in container sizing, flex base/hypothetical sizing, flexible-length resolution, cross-size stretching, alignment, RTL, baselines, absolute positioning, and scrollbar/overflow handling. Headline user-visible gaps: container `align-items` is ignored; `align-items/align-self: stretch` does not stretch auto-cross items to the container/line; auto-height wrapped containers are sized to one line instead of the sum of lines; `flex-basis` can be ignored when the line is exactly sized; automatic minimum sizes and min/max clamping of items are wrong; baseline alignment and flex container baselines are absent; absolute flex children are placed without alignment/inset/sizing logic and their subtrees are not re-laid-out; RTL is ignored; and no Taffy XML/HTML fixture is executable against the Zig tree. There is also no runtime verification available in this environment (`zig` is not installed), so the findings below are from code reading only.

## Covered and behaviorally aligned

- **Enums, defaults, predicates**: `FlexDirection`/`FlexWrap` values, defaults, `is_row`/`is_reverse`/`is_multi_line`/`is_balance` (`src/style/flex.zig:7-84`) match `style/flex.rs:85-262`, including `balance`/`balance_reverse`.
- **Record shape**: `FlexItem`, `FlexLine`, `AlgoConstants` carry the same named fields as Rust (`src/compute/flexbox.zig:30-111` vs `flexbox.rs:26-227`), though many are unused (see below).
- **Anonymous item filtering**: `display:none` and `position:absolute` children are skipped and sibling index order is preserved (`src/compute/flexbox.zig:252-254` vs `flexbox.rs:661-665`); auto-margin flags and padding/border/overflow/contain are copied.
- **Greedy line collection shape**: consecutive items are split into lines against the container main size with gap only between items (`src/compute/flexbox.zig:395-438` vs `flexbox.rs:1101-1184`) — correct for the common definite-main-size, LTR case.
- **Alignment helper ports**: `apply_alignment_fallback`, `compute_alignment_offset`, `resolve_self_alignment_safety` (`src/compute/common/alignment.zig:7-61`) are faithful ports of `common/alignment.rs:11-117` and are used for align-content and cross `safe` fallback.
- **Basic justify-content**: LTR positional and distributed offsets via a cursor match Taffy for the exercised cases; the port's `space-between` unit test encodes correct positions (`src/compute/flexbox.zig:908-921`).
- **Main-axis auto margins**: free space is shared equally among auto margins (`flexbox.zig:702-716`), matching `flexbox.rs:2131-2189`; unit-tested.
- **Wrap-reverse basic stacking** and **row-reverse basic flex-start placement**: unit tests assert Taffy/CSS expected coordinates (`flexbox.zig:886-906, 935-946`).
- **Simple grow/shrink with a clamped item**: the `flexing freezes max violations` unit test result matches the reference intent (`flexbox.zig:923-933`), though the algorithm differs (below).
- **`flex-wrap: balance` line breaking**: `naive_line_item_counts` + `LineSizes` (`flexbox.zig:443-581`) mirror Taffy's test oracle (`flexbox.rs:3124-3615`): same f64 prefix sums, zero-sized-item rule, line-limit constraint, and "largest end first" tie-break; the three Zig balance tests assert the same expectations as Rust's `zero_sized_item_rule`.
- **Container box-sizing/padding/border basics** and min/max clamping of the container outer size are applied (`flexbox.zig:139-148` vs `flexbox.rs:241-276`), modulo `min > max` (divergent item below).
- **Rounding**: `round_layout` is ported and wired (`src/compute/mod.zig:139-169`), same intent as `compute/mod.rs`; not verified against the single `rounding.rs` test.

## Missing or unimplemented

Each item: Rust behavior → Rust ref; Zig status → Zig ref; impact; severity.

1. **Container `align-items` never reaches items — BLOCKER.** Rust: item `align_self` = `child_style.align_self().unwrap_or(constants.align_items)` with self-relative resolution (`flexbox.rs:709-713`, constants at `562`). Zig: `child.style.align_self orelse AlignItems.stretch` (`flexbox.zig:270`); `AlgoConstants.align_items` is assigned (`226`) but never read (grep hit count 1). Impact: `align-items: center/flex-end/baseline` has no effect unless every child sets `align-self`; most `align_items_*`, `wrap_row_align_items_*`, `align_content_not_stretch_with_align_items_stretch` fixtures fail.
2. **Baselines and `align-items/self: baseline` — BLOCKER.** Rust: measures child baselines and offsets baseline-aligned rows (`flexbox.rs:1877-1955`, `2259-2339`); outputs container first baseline (`505-530`), suppresses it under `contain` (`316-319`). Zig: `calculate_children_base_lines` sets each item's baseline to its own hypothetical cross size (`flexbox.zig:317-319`); cross alignment has no `.baseline` branch (`772-776`); `compute_flexbox_layout` returns `from_outer_size` with no baselines (`201`); the measure ABI returns `Size(f32)`, not `LayoutOutput`, so a measure function cannot supply a baseline (`src/tree/traits.zig:12-16`). Impact: baseline fixtures and `tests/hand_written/baseline.rs` semantics unsupported.
3. **Stretch to the line/container is wrong — BLOCKER.** Rust: single-line definite-cross container sets line cross = inner cross (`flexbox.rs:1964-1976`); stretched auto-cross items get `line_cross - margins` clamped by min/max ignoring aspect ratio (`2064-2110`). Zig: the phase function `calculate_cross_size` is dead (`flexbox.zig:321-323`); line cross = max item hypothetical (`161-162`, `609-613`); stretch uses that (`685-697`, `760`). Impact: an auto-height child in a fixed-height single-line flex row stays at its natural height instead of filling the container; most `align_*_stretch`, `*_fill_*`, `percentage_height_in_stretched_flex_item` behavior wrong.
4. **Container cross size from lines — BLOCKER.** Rust: `determine_container_cross_size` = sum of line cross sizes + cross gaps + inset, min/max-clamped (`flexbox.rs:2353-2376`). Zig: function dead (`flexbox.zig:381-383`); `outer` is fixed from known/style/available/natural before phases (`138-148`) and `natural_size` takes the single tallest item (`615-625`). Impact: auto-height wrapped containers are one line tall, so later lines overflow the container box.
5. **Container main size determination — MAJOR.** Rust: `determine_container_main_size` with min/max/floors, per-line contributions, `content_flex_fraction`, min-content/max-content formulas and the balance fit-content rule (`flexbox.rs:1289-1593`), then percentage gaps are re-resolved (`397-405`). Zig: `determine_container_main_size` (`305-308`) return value is discarded (`149`); no contribution logic; gaps are resolved once against the parent's width (`130`). Impact: fit-content/intrinsic sizes of flex containers, content-based sizing, and percentage gap re-resolution are wrong.
6. **Available-space determination — MAJOR.** Rust subtracts margins and content-box insets and honours known sizes (`flexbox.rs:753-782`). Zig: `determine_available_space` is a no-op returning its input (`flexbox.zig:240-243`) and its result is unused (`136`).
7. **Flex base + hypothetical main sizes are not measured or clamped — BLOCKER.** Rust: flex base from definite basis / aspect-ratio transfer / content measurement, floored by item padding+border; `resolved_minimum_main_size` from min-content measurement plus `overflow` automatic minimum; hypothetical = basis clamped by resolved min and transferred max (`flexbox.rs:812-1081`; overflow auto-min `1041-1042`; aspect transfer `977-981`). Zig: `determine_flex_base_size` copies the pre-pass measured size into `flex_basis` only (`flexbox.zig:294-298`); `inner_flex_basis` never subtracts item padding/border (`297`, and the generate-time computation at `283` uses the *container's* inset and is overwritten); `hypothetical_inner_size` is the generic pre-pass size (`284`) and is never updated; `resolved_minimum_main_size = min_size orelse 0` (`277`). Impact: `flex-basis: auto`/content items, explicit basis smaller than content when frozen, automatic minimum sizes, and min/max item clamping are wrong.
8. **Sizing keywords (`min-content`, `max-content`, `fit-content(...)`, `stretch`, `content`, `calc`) — MAJOR.** Rust resolves them in flex basis and item size (`flexbox.rs:921-955`), cross size (`1834-1841`), and absolute children (`2738-2753`). Zig: `Dimension.resolve` returns null for every keyword (`src/style/dimension.zig:196-202`) and `flexbox.zig` never references `compute/common/sizing_keyword.zig` (only block/grid do: `compute/block.zig:323`, `compute/grid/types/grid_item.zig:253`). Impact: keyword-sized flex items fall back to the measured size; `flex_line_count.rs` fit-content cases fail.
9. **Aspect ratio in the flex algorithm — MAJOR.** Rust applies it to child size/min/max (`flexbox.rs:667-693`), flex base from definite cross (`977-981`), transferred min/max clamps (`831-832`, `1807-1810`), and absolute children (`2718-2772`). Zig stores `aspect_ratio` (`flexbox.zig:269`) but never reads it; only leaf sizing uses it (`compute/leaf.zig:100-102`). Impact: `aspect_ratio` fixtures and vertical/horizontal transfer inside flex items diverge.
10. **RTL — MAJOR.** Rust: direction drives `resolve_self_relative` (`flexbox.rs:709-713`), RTL row main start (`2441-2459`, `2551-2561`), RTL column cross (`2259-2266`, `2558-2560`), absolute placement (`2690-2694`, `2845-2860`). Zig: `layout_direction` is stored (`flexbox.zig:213`) and never read; placement always begins at `inset.left`/`inset.top` (`777-780`). Impact: all `*_rtl` fixture variants (~1/4 of the generated flex XML tests).
11. **Absolutely-positioned flex children — BLOCKER.** Rust implements sizing keywords, aspect ratio, min/max, inset-derived sizes, static-position fallback per `justify-content`/`align-self` with `safe`, CSS2 auto-margin rules, RTL and scrollbar offsets, recursive child layout, and overflow contribution (`flexbox.rs:2663-3073`). Zig: simple left/right/top/bottom placement, no alignment at all (ignores `align_self`/`justify_content`), no aspect ratio, no min/max clamp, auto margins taken as 0, insets resolved against the padding box, and no recursive re-layout of descendants (`flexbox.zig:789-808`). Impact: `absolute` flex fixtures (66 base names) fail; a resized absolute child's own subtree keeps pre-pass sizes.
12. **Scrollbar gutter on the flex container — MAJOR.** Rust reserves `scrollbar_width` via transposed `overflow`, adds it to `content_box_inset` (left for RTL), uses it in available/main/cross/absolute math (`flexbox.rs:567-585, 594, 2362, 2666-2671`). Zig hard-codes `scrollbar_gutter = {0,0}` and `content_box_inset = padding+border` (`flexbox.zig:223-224`); container `overflow`/`scrollbar_width` are never read. Impact: `overflow: scroll` flex containers do not reserve gutters.
13. **`content_size` / scrollable overflow from flex placement — MAJOR.** Rust unions per-item contributions with contain/overflow clipping, RTL mirroring and scroll-container padding extension (`flexbox.rs:2519-2534, 2644-2656, 3046-3069`). Zig: flexbox emits no overflow rect; a generic post-pass derives a rect from children's stored locations (`src/compute/mod.zig:27, 38-58`) and misses flex-specific offsets/padding/RTL/contain; `Layout.content_size` is never written (`src/tree/layout.zig:112`). Impact: `scroll_size`/`scrollable_overflow` and `overflow` fixture results diverge.
14. **`RunMode::ComputeSize` / `RequestedAxis` — MAJOR.** Rust short-circuits complete known sizes and supports single-axis measurement (`flexbox.rs:278-299, 472-474`) used by `measure_child_size`. Zig flexbox ignores `run_mode` and `axis` and always performs full layout (`flexbox.zig:113-201`); the dispatcher always lays children out fully (`compute/mod.zig:23-36`). Impact: public `compute_child_layout(ComputeSize)` semantics and measure-call/caching behavior differ.
15. **`min_max_definite_size` (`max <= min` ⇒ `min`) and clamp order — MAJOR.** Rust `maybe_clamp` applies max first then min so `min` wins when `max < min` (`src/util/math.rs:47-55, 85-86`), and flexbox short-circuits `max <= min` to `min` (`flexbox.rs:269-276`). Zig clamps `@min(max, @max(min, v))`, so `max` wins (`clamp_optional` `src/compute/leaf.zig:181-184`; `clamp_resolved_size` `src/style/dimension.zig:290-296`, applied at `flexbox.zig:145-146`). Impact: Taffy's `min_max_overrides.rs::min_overrides_max` expectation (min 100 / max 10 ⇒ 100) yields 10 in Zig, for both leaf and container paths.
16. **`divided_cross_space` / `flex-line-count` — MAJOR.** Rust divides definite cross available space by the requested line count when wrapping (`flexbox.rs:211-227, 552`) and tests it in `tests/hand_written/flex_line_count.rs` (5 tests). Zig: method is a stub returning its argument (`flexbox.zig:107-110`); `AlgoConstants` has no `line_count`/`is_balance` fields (`81-105`); `flex_line_count` only feeds the balance minimum (`153`, `595`). Impact: `flex-line-count` cross-size measurement cases fail.
17. **`item_known_dimension_definiteness` — MAJOR.** Rust computes per-item main/cross definiteness for child layout (`flexbox.rs:1266-1286`). Zig defines it (`flexbox.zig:300-303`) but never calls it; `final_layout_pass` passes `{true,true}` (`735`). Impact: percentage descendants resolve against sizes the reference treats as indefinite.
18. **Hidden/collapsed children and baseline suppression — MINOR.** Rust explicitly lays out `box_generation_mode == None` children and resets output baselines under `contain: layout` (`flexbox.rs:489-503, 316-319`). Zig relies on the dispatcher pre-pass for hidden children and never suppresses baselines (moot today because it emits none). No `visibility: collapse` in either (Rust TODO at `448`).

## Present but behaviorally divergent

1. **`resolve_flexible_lengths` — BLOCKER.** Rust classifies the line as growing/shrinking/exactly-sized from summed hypothetical outer sizes, freezes zero-factor and basis-vs-hypothetical items, handles the `sum(flex factors) < 1` partial-fill rule, clamps against `resolved_minimum_main_size` and max, accumulates signed total violation and freezes min/max violators accordingly (`flexbox.rs:1600-1787`). Zig resets targets to the *measured* size, iterates a fixed `n+2` budget, freezes only items whose clamp moved them, and never implements the sub-1 factor rule or automatic minimum (`flexbox.zig:627-679`). Impact: `flex-basis` ignored in exactly-sized lines, `flex-grow: 0.5` under-fills, min-content min sizes not respected.
2. **`collect_flex_lines` — MAJOR.** Rust requires a definite known main size, handles max-content (one line), min-content (one item per line), clamps the wrap limit by max/min size for indefinite containers, and wraps on outer hypothetical size (`flexbox.rs:1101-1184`). Zig wraps whenever `available_main > 0`, ignores definiteness/max/min, and measures items by `flex_basis + margins` (`flexbox.zig:395-438`). Impact: wrong line counts for indefinite/intrinsic containers and basis/hypothetical differences.
3. **`justify-content` fallback and distribution — MAJOR.** Rust applies `apply_alignment_fallback` (safe/distribution fallbacks for ≤1 item and overflow) and computes a per-item offset including reverse handling (`flexbox.rs:2172-2188`). Zig passes the raw keyword (`flexbox.zig:726`) and uses one start offset plus a cursor. Impact: `safe` `justify-content` fixtures (`flex_safe_justify_content_falls_back_to_start_on_overflow`) and single-item `space-*` fallbacks fail.
4. **Cross-axis alignment mapping — MAJOR.** Rust distinguishes start/flex-start/end/flex-end/center/baseline/stretch against `wrap-reverse`, RTL columns and safe fallback (`flexbox.rs:2259-2339`). Zig handles only `.end`/`.flex_end`/`.center`, everything else 0 (`flexbox.zig:772-776`), and cross auto margins are computed per item with a floored free space and share count (`762-770`) where Rust distributes even a negative free space (`free/2`) without flooring and skips alignment for auto-margin items (`2204-2249`). Impact: RTL/wrap-reverse cross alignment, `align-self: start/end` distinctions.
5. **Item construction/box model — MAJOR.** Rust resolves child size through `percent_resolution_size` gated on definite main size, applies aspect ratio + box-sizing adjustment, resolves min/max with box-sizing, keeps `inset`, and floors `flex_basis` by item padding+border (`flexbox.rs:652-739, 1017-1031`). Zig resolves against the parent width/height directly, never adds box-sizing adjustment to item styles, uses the generic pre-pass size for `size`, and never floors basis by padding+border (`flexbox.zig:249-292`).
6. **Measure-function integration — MAJOR.** Rust measures items per phase with tailored inputs (flex base under max-content, min-content for auto min, hypothetical cross, baseline layouts) via `measure_child_size`/`compute_child_layout(ComputeSize)` (`flexbox.rs:1006-1014, 1044-1058, 1843-1867, 1905-1939`). Zig runs one generic pre-pass over every child with no known dimensions and the parent's available space (`compute/mod.zig:73-84`) and reuses that size; the public `compute_layout_with_measure` drops the measure callback parameter entirely (`src/tree/taffy_tree.zig:370-372` vs `taffy_tree.rs:897-908`). Impact: `measure.rs` expectations (counts/dimensions) and remeasure-after-grow/shrink/stretch differ.
7. **Child `Layout` records — MAJOR.** Rust writes `order`, `size`, `scrollable_overflow_rect`, `scrollbar_size`, `location`, `padding`, `border`, `margin` through `set_unrounded_layout` (`flexbox.rs:2498-2511`). Zig writes only `location` and `size` (`flexbox.zig:777-782`); leaf children never get padding/border/margin/order recorded. Impact: `layout_of(child).padding/margin/border/order/scrollbar_size` are wrong for flex children.
8. **Container sizing inputs — MAJOR.** Rust computes `styled_based_known_dimensions` only under `SizingMode::InherentSize`, applies aspect ratio and box-sizing to container min/max, and normalizes definiteness flags (`flexbox.rs:247-314`). Zig ignores `sizing_mode` and definiteness inputs (`flexbox.zig:139-146`) and uses its own `known_dimensions_are_definite` copy.
9. **`flex-wrap: balance` plumbing — MINOR.** Zig uses the naive O(lines·items²) DP (`flexbox.zig:520-580`) instead of Rust's divide-and-conquer (`flexbox.rs:3268-3424`); Rust asserts equivalence to the naive oracle over 5000 random cases, so results should agree. However Zig passes `hypothetical_outer_size` and a limit derived from the (already wrong) container content size, and treats an indefinite size as the natural size rather than infinity (`583-607` vs `1191-1258`).
10. **`FlexWrap` parsing — MINOR.** Rust accepts keyword sequences such as `wrap balance`/`balance-reverse` via CSS parser (`style/flex.rs:142-183`). Zig `from_str` accepts only the exact five single tokens (`src/style/flex.zig:55-63`).
11. **Zig-only behavior.** `compute/mod.zig:73-84` lays out every child before any container algorithm runs, so flex base sizes are derived from a generic `PerformLayout` pass (Taffy never does this); `content_size_hint` (`flexbox.zig:245`) and `item_known_dimension_definiteness` (`300-303`) are dead, and `AlgoConstants.is_scroll_container`/`line_count`/`is_balance` are absent; `constants` fields `min_size`/`max_size`/`margin`/`container_size` are `null`/zero and unused.

## Feature flags / API surface affected

- Zig has no feature gating: `flexbox_balance`, `content_size` and `detailed_layout_info` are always compiled in (`src/style/flex.zig:38-63`, `src/tree/layout.zig:112, 156`). Taffy's default features enable all three (`Cargo.toml:36-47`), so this alone is not a behavior gap.
- Correction to the task brief: at the pinned rev (v0.14.0-7) `DetailedLayoutInfo` has only `Grid` and `None` variants (`taffy/src/tree/layout.rs:400-410`); there is **no** flex `flex_line_count` output to port. Zig's union matches (`src/tree/layout.zig:156`), but `set_detailed_grid_info` is the only population path.
- `TaffyTree.compute_layout_with_measure` loses the `measure_function` parameter (`src/tree/taffy_tree.zig:370-372` vs `taffy_tree.rs:897-908`, whose callback is `FnMut(LayoutInput, NodeId, Option<&mut NodeContext>, &Style) -> LayoutOutput`). `MeasureFunc` returns `Size(f32)` instead of `LayoutOutput`, so callbacks cannot report baselines or a scrollable overflow rect (`src/tree/traits.zig:12-16`).
- `Layout.content_size` exists but is never assigned (`src/tree/layout.zig:112`); the `content_size` feature's observable output is `scrollable_overflow_rect`, which is populated by a generic post-pass rather than by flexbox (see Missing #13).
- Flex children's `Layout.padding/border/margin/order/scrollbar_size` fields are never set by the flex algorithm, so accessors such as `Layout.content_box_size()` are wrong for flex children (Missing/Divergent #7).
